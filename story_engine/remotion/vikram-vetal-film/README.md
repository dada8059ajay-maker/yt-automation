# Vikram-Vetal — 2D Animation Film (Raat Ke Kisse)

Real 2D animation for the Raat Ke Kisse horror channel — topic #2 after
Ashwatthama. 100% code-drawn scenes (SVG shapes in Remotion): the king
actually WALKS carrying the corpse, tally marks appear one by one for the
24 nights, the tantrik's fire grows and dies. No photos at all in this
film (Ashwatthama mixed photos in; this one does not need them).

### How durations are set (measured, not guessed)

Every WAV was ffprobe'd; the numbers match the Maya run's `result.json`
exactly (total 181.92 s). `gapAfterSec`: 0.45 s between lines, 1.0 s
after a take-ending line (a02, a04, a05, a07, a09). Frames are computed
in `src/data/takes.ts`: `frames = round((audioSec + gapAfterSec) × 30)`.
`src/RemotionRoot.tsx` reads the durations from that file — no duration
is hand-typed in the root.

### Audio wiring — per-line WAVs

Each line's own WAV (`public/audio/a01.wav` … `a12.wav`, copied from
`../poc-vikram-vetal-6min/audio-maya/`) is played by that line's shot
(`<Audio>` inside the line's `<Sequence>` in
`src/components/LineScene.tsx`). **No ffmpeg concatenation step
anywhere.**

### Title / end cards — Zero Spoiler Rule

`public/photos/title.jpg` ("विक्रम और वेताल / श्मशान का मुर्दा") and
`end.jpg` ("कथासरित्सागर / वेतालपंचविंशति") are pre-rendered with
`make_cards.py` (PIL + Noto Sans Devanagari, same pattern as
Ashwatthama). Neither card shows the twist. Cards are shown static
(no zoom) with embers + fog drifting over them.

### Subtitles — .ass READY, not yet muxed

`subtitles/vikram-vetal.ass` (12 events, generated by
`gen_subtitles.py` from the same timeline numbers as `takes.ts`;
last subtitle ends 0:03:13.12, film ends 0:03:18.57). Mux it into the
rendered mp4 with ffmpeg + a Devanagari font AFTER the GitHub render.
ffmpeg drawtext is never used (Devanagari conjuncts break).

### No on-screen text

No Devanagari text is drawn by Remotion anywhere: rendering Devanagari
would need a font bundled for the GitHub runner. Title and end cards
are pre-rendered images, so their text is safe.

## Run locally

```bash
cd poc-vikram-vetal-2d
npm install          # installs pinned deps, writes package-lock.json
npm start            # Remotion Studio — live preview at localhost:3000
npm run render:film  # whole film -> out/vikram-vetal-film.mp4
npm run render:take  # one take (T01) -> out/vikram-vetal-t01.mp4
npm run typecheck    # tsc --noEmit
npm run compositions # list registered compositions (validates the bundle)
```

Note: `node_modules/` in this workspace is currently a symlink to
`../poc-ashwatthama-2d/node_modules` (same pinned Remotion 4.0.545) to
avoid a second 782 MB install. It is gitignored and is NOT part of the
commit — the GitHub workflow runs `npm ci` from the lockfile.

A full local render of the film is slow on a small VM — prefer stills
(`npx remotion still src/index.ts VikramVetalFilm <frame> out/still.png`)
for checking shots, and the GitHub workflow for the full render.

## GitHub Actions workflow

File: `.github/workflows/remotion-film.yml` (film render).

**It must be copied to the repo-root `.github/workflows/` as
`remotion-vikram-vetal-film.yml` to actually run** — GitHub only
discovers workflows there. Set the `PROJECT_DIR` env in the file to the
path where this project is committed in that repo (`"."` if this becomes
its own repo).

See `FILM-BUILD-NOTES.md` for the exact commit + dispatch steps.
